## 0. 通則（所有小工具共用）

### 0.1 定位
- 位置：`tools/<工具名>/`，是**獨立於網頁系統的本機 CLI**。
- **不參與 `npm run build`、不部署上線**（`tsconfig` 只涵蓋 `src` 與 `vite.config.ts`）。
- 網頁的 `/tools` 頁只放使用說明，不呈現也不儲存任何查詢結果。

### 0.2 為什麼不做在網頁上
瀏覽器的同源政策禁止網站登入並讀取另一個網域的內容，因此網頁**在技術上無法**
代為登入外部系統、處理驗證碼或下載檔案。唯一繞法是架伺服器代抓，
但那會讓個案明細經過雲端主機，與個資要求牴觸，故不採用。

### 0.3 個資保護總則
凡工具會接觸到含個人資料的檔案，一律遵守：

| 規範 | 作法 |
| --- | --- |
| 不上雲 | 全程本機執行；不寫入 Firestore、不呼叫任何外部 API、不上傳檔案 |
| 原始明細用完即刪 | 只落在該工具的 `out/raw/`，統計後自動刪除（`--keep-raw` 才保留） |
| 產出只有統計數字 | 最終報表不含任何個人欄位 |
| 不進版控 | `.gitignore` 已排除 `tools/**/out/` |
| log 不印明細 | 只記錄流程、筆數與**欄位名稱**（欄名屬檔案結構，非個人資料） |
| 探測模式不取資料 | 只記錄欄位／按鈕／下拉選項名稱；資料列表（列數 > 5 的表格）內元素一律跳過；5 碼以上連續數字遮蔽；不截圖 |
| 驗證碼不自動破解 | 由使用者本人辨識輸入，不繞過來源系統的防自動化機制 |
| 帳密不硬寫 | 僅從該工具目錄的 `.env` 讀取（已 gitignore），且**禁用 `VITE_` 前綴**以免被打包進前端 |

### 0.4 執行方式
**一般使用一律雙擊 `捷徑/` 資料夾內的批次檔，不需輸入任何指令。**
批次檔會先確認 Node.js 是否存在（沒有就顯示官網下載連結），並在缺少套件時自動 `npm install`；
內容維持純 ASCII 訊息，避免主控台中文亂碼。

> ⚠ **`.bat` 內絕對不能出現中文，連 `rem` 註解也不行**（2026-07-31 實際踩到）。
> 主控台是 DBCS 代碼頁（cp950），UTF-8 的中文位元組會被當成 Big5 的前導位元組，
> **把後面的字元連同換行一起吃掉**，於是 `if (...)` 區塊被切碎、殘餘片段被當成指令執行，
> 畫面上出現一整串「'ut' 不是內部或外部命令」這種看不出原因的錯誤。
> 需要中文說明就寫在 README 或網頁的 `/tools` 頁，不要寫進批次檔。
>
> ⚠ **含中文的 `.ps1` 必須存成「UTF-8 with BOM」**：Windows PowerShell 5.1
> 讀沒有 BOM 的檔案時會用系統 ANSI 代碼頁解碼，中文會變亂碼（連字串內的路徑也會壞掉）。

### 0.5 執行紀錄
每次執行的完整過程都會寫入該工具的 `out/last-run.log`（含失敗時的 frame 狀態），
排查問題不需請使用者抄寫終端機訊息。內容依設計不含個案明細。

### 0.6 可攜版（不能安裝軟體的電腦）
公家電腦通常不允許安裝 Node.js。`scripts/make-portable.ps1`
（雙擊 `捷徑/建立可攜版.bat`）會把工具打包成一個可整包複製的資料夾：

| 項目 | 說明 |
| --- | --- |
| 產出位置 | 專案旁的 `可攜版/EMS工具/`（已 gitignore） |
| 內容 | 工具的 `.mjs`、精簡版 `package.json`、必要套件、**Node.js 本體**、專用啟動捷徑 |
| 大小 | 約 150MB（Node.js 約佔一半） |
| 需在有網路的電腦執行 | 會下載 Node.js 官方 zip（版本取自 `nodejs.org/dist/index.json` 最新 LTS） |
| **不會複製** | `.env`（帳密）與 `out/`（個案資料）——避免隨身碟遺失造成外洩 |
| 目標電腦仍需具備 | Chrome 或 Edge（自動化用的是該電腦本機的瀏覽器） |

套件清單刻意只列 `playwright-core`、`pdfjs-dist`、`exceljs`、`xlsx` 四個，
版本自主專案的 `package.json` 讀取，不會與主專案的版本不一致。

## 1. 救護紀錄表查詢（到院前預警比率）

位置：`tools/ems-report/`

### 1.1 目的
自「桃園市政府消防局緊急救護管理系統」（`https://emsdt.tyfd.gov.tw/EmmWeb/`）
取得指定月份的救護紀錄，統計**各分隊的「到院前預警案件數 ÷ 總案件數」比率**。

### 1.2 執行方式
| 捷徑（`捷徑/` 資料夾內） | 用途 |
| --- | --- |
| `救護預警統計.bat` | 產生上個月的各分隊比較表（**日常使用就是這個**） |
| `設定登入帳密.bat` | 用記事本開啟 `.env` 填帳密，省去每次輸入（驗證碼仍須本人輸入） |
| `救護預警統計-設定用.bat` | 頁面結構探測，系統改版時才用 |
| `檢查增減試算表.bat` | 確認增減用的 Google 試算表讀不讀得到，並列出欄位結構 |

指令列等價寫法：

| 指令 | 用途 |
| --- | --- |
| `npm run tool:ems -- run` | 完整流程，預設查「上個月 1 號 ~ 最後一天」 |
| `npm run tool:ems -- run --month=2026-06` | 指定月份 |
| `npm run tool:ems -- run --keep-raw` | 保留原始匯出檔（含個資） |
| `npm run tool:ems -- probe` | 自動探測頁面結構（使用者只需登入） |
| `npm run tool:ems -- probe --manual` | 改為手動點選的探測模式 |
| `npm run tool:ems -- check-sheet` | 檢查增減用的 Google 試算表 |
| `npm run tool:ems:test` | 全部單元／整合測試 |

以本機已安裝的 Chrome 執行（`playwright-core` + `channel: 'chrome'`），不另外下載瀏覽器。
**Node.js 並非 Windows 內建**，該台電腦需自行安裝。

### 1.3 自動化流程
1. 開啟登入頁；帳密可自 `.env` 代填，**驗證碼由使用者在瀏覽器輸入**。
   程式輪詢等待登入完成，再等 `contentSidemenu`／`contentFrame` 兩個 frame 真正出現才續行。
2. 左側選單 → 報表系統 → 救護紀錄表查詢。
3. 填入共同查詢條件，**填完一律回讀驗證**：
   - 查詢期間（起日 `00:00:00`、迄日 `23:59:59`）
   - 救護狀態＝「已結案」
   - **送醫情形＝「送醫」**（未運送案件如誤報、拒送、現場死亡不會有到院前預警，
     算進母數會稀釋比率）
4. 院前預警不設限 → 查詢 → 匯出 Excel（**總案件數**）。
5. 院前預警＝「到院前傳送預警」→ 查詢 → 匯出 Excel（**預警案件數**）。
6. 本機解析兩份 Excel，依分隊彙總。
7. 讀取增減試算表，扣除期間內應排除的案件（見 1.7）。
8. 輸出兩個分頁的報表後刪除原始明細。

彈出式視窗封鎖不需另外處理：自動化瀏覽器預設允許彈出視窗與檔案下載。

### 1.4 目標系統的實際結構（探測結果）

### 1.6 報表格式
比照使用者既有的人工報表（`6月份到院前預警比例.xlsx`），輸出**兩個分頁**：

| 分頁 | 內容 |
| --- | --- |
| `到院前預警比例` | 各大隊合計列 ＋ 其轄下分隊（依 `BRIGADES` 設定的官方順序） |
| `排序` | 各分隊依**到院前預警率由高到低** |

兩個分頁格式相同：
- 第 1 列為標題並跨 4 欄合併，內容為 `本局{起}-{迄}到院前預警案件執行率`（例：`本局6/1-6/30…`）
- 第 2 列欄位標題：（留白）｜`有送醫有預警案件`｜`有送醫案件`｜`到院前預警率`
- 比率欄以數值寫入並套 `0.00%` 格式，可直接在 Excel 內再排序或製圖
- **大隊列為紅底深紅粗體字**（`REPORT_FORMAT.brigadeRowStyle`，色碼可自行調整），
  一眼即可與轄下分隊區分；`排序`分頁只有分隊，故無上色
- **每一格四邊皆有 `thin` 框線、文字水平垂直置中**
- **字級：內文 12、第一列標題 16**；列高設為約字級的兩倍（標題 32、其餘 24），留出上下空白避免擁擠
- **欄寬依內容自動計算**（中日韓字元以兩倍寬計，再乘字級比例並加邊距），
  `columnWidths` 僅作為下限，確保文字不會被截斷

> 報表檔若正被 Excel 開啟會無法覆寫（EBUSY/EPERM），此時輸出明確的中文提示
> 並說明查詢結果不需重跑、只差寫檔這一步。

> **輸出用 ExcelJS 而非 SheetJS**：SheetJS 的免費版**不會寫入儲存格底色**
> （樣式屬付費功能，寫進去讀回來會變成 `patternType: none`）。
> 讀取匯出檔仍用 SheetJS，因為 ExcelJS 不支援舊的 `.xls` 格式。

大隊與轄下分隊的對應表定義於 `config.mjs` 的 `BRIGADES`（4 大隊、41 分隊），
順序取自既有報表。匯出檔中出現但不在對應表內的單位會歸入「未對應大隊」並在紀錄檔提出警告，
**不會被默默丟掉**。

### 1.7 統計規則
- **分隊欄位以「內容」判定而非欄名**：值以「分隊／大隊／中隊」結尾的比例達 80% 以上者即為分隊欄。
  內容判斷不出來時才退回欄名比對（`SQUAD_COLUMN_CANDIDATES`），且「包含」比對取最短欄名。
- 分隊比率＝該分隊預警案件數 ÷ 該分隊送醫案件數；送醫案件為 0 時比率為 `null`（不做除以零）。
- **大隊比率＝該大隊預警案件總數 ÷ 送醫案件總數（加權）**，使用者於 2026-07-28 確認採此算法。
  ⚠ 使用者先前的人工報表取的是「各分隊比率的平均」，兩者相差約 0.2~1.0 個百分點
  （案件量小的分隊在平均法中權重被放大），故新舊報表的大隊數字不會完全相同，屬預期差異。
- `排序`分頁依預警率由高到低；比率相同時案件多的在前，再相同則依名稱，確保輸出順序穩定。
- **合理性檢查**：資料超過 100 筆卻只分出少於 3 個分隊時直接中止並列出實際欄名，
  避免產出明顯錯誤的報表。
- 解析失敗時**保留原始檔**並輸出「只有欄名與筆數」的診斷資訊，不輸出任何資料格內容。

#### 增減試算表的扣除規則（v1.11.6 起）
使用者維護一份 Google 試算表，列出應自統計中排除的案件。規則（2026-07-28 確認）：

- 讀**第一個分頁**（`EMS_ADJUST_SHEET_GID` 留白即為第一個分頁）。
- 每一列代表一件應排除的案件；**日期落在查詢期間內**者才計入。
- **只扣該分隊的送醫案件數（分母），預警案件數（分子）不動**
  ——把這些案件排除在評比之外。使用者於 2026-07-29 再次確認採此算法。
  ⚠ **與 6 月以前的人工報表口徑不同**：舊報表是把同一批案件**加到分子**
  （視為實際有預警、只是系統未記錄），全局比率因此高約 0.02 個百分點，
  跨期間比較趨勢時須留意。詳見 1.11。
- 日期欄與分隊欄**以內容判定**（日期可解析比例 ≥ 70%、以分隊/大隊/中隊結尾比例 ≥ 70%），
  不依賴欄名，使用者改欄名不影響。
- 日期容錯：`2026-06-01`、`2026/6/1`、`2026年6月1日`、後接時間、以及**民國年**（`115/6/1`）。
- 試算表寫「桃園」而非「桃園分隊」也能對應（比對時自動補「分隊」）。
- **找不到對應分隊、或扣到分母小於分子時會提出警告**，不會默默套用。
- **日期空白的列屬正常情形**（使用者 2026-07-28 確認），一律不列入扣除，
  只以一般訊息附記筆數，不視為警告。
- 未設定 `EMS_ADJUST_SHEET_URL` 時略過扣除，不影響主流程。

存取方式：以 Google 試算表的 CSV 匯出網址讀取，**免 API 金鑰**，
但該試算表須設為「知道連結的任何人 → 檢視者」。

### 1.8 實跑踩過的坑（維護時務必先看這段）

| 現象 | 真正原因 | 對策 |
| --- | --- | --- |
| 找不到 `contentSidemenu` | 「驗證碼欄位消失」只代表表單送出，frameset 尚未建好 | 等必要 frame 真正出現（`waitForAppReady`） |

| 打驗證碼時焦點一直被搶 | 等待迴圈每秒重填帳密並把游標移到驗證碼欄 | **只在欄位空白時才代填**，填完只移動一次焦點 |

| 讀 Google 試算表得到 HTTP 400 | 預設帶了 `gid=0`，但**第一個分頁的 gid 未必是 0**（原始分頁被刪過就會變） | 未指定 gid 時**不帶該參數**，Google 即回傳第一個分頁；帶了 gid 而收到 400 時自動退回不帶 |

## 2. 解鎖救護紀錄表

位置：`tools/ems-report/`（與第 1 章同一個工具，共用登入與導航模組）

### 2.1 目的
把指定 TEMSIS 的案件由「已結案」調整為「未結案」。人工流程一筆要在四個畫面之間來回，
多筆時非常耗時，且案件內有多張紀錄表時容易解錯張。

### 2.2 ⚠ 現況：試跑版，只定位不解鎖
**本版絕不按下「調整為未結案」**，只查詢、比對，並回報「該解哪一張」。

| 理由 | 說明 |
| --- | --- |
| 動作不可復原 | 解鎖是寫入系統的動作，解錯張沒有還原鍵 |
| 三個畫面尚未探測 | 案件列表、案件內部、救護紀錄表的實際結構還沒實跑確認過 |

`--execute` 參數已保留但會被明確拒絕。等使用者用試跑確認每一筆都定位正確後，
才會補上真正按下按鈕的程式碼。

### 2.3 執行方式
| 捷徑 | 用途 |
| --- | --- |
| `解鎖救護紀錄表.bat` | 貼上 TEMSIS 後自動執行（**日常使用就是這個**） |
| `建立可攜版.bat` | 打包成隨身版，給不能安裝 Node.js 的電腦（見 0.6） |

指令列等價寫法：

| 指令 | 用途 |
| --- | --- |
| `npm run tool:ems -- unlock` | 執行後在終端機貼上 TEMSIS（一行一個，空白行結束） |
| `npm run tool:ems -- unlock --temsis=A,B` | 直接指定，省去互動輸入 |

TEMSIS 一行可貼多個（以空白、逗號、分號分隔），重複的會自動去除。

### 2.4 自動化流程（每一筆 TEMSIS 各跑一輪）
1. 報表系統 → 救護紀錄表查詢；查詢期間設為**今天往回推兩個月**（`UNLOCK.lookbackMonths`）。
2. 填入 TEMSIS → 查詢。
3. 點該列的「救護紀錄PDF」，讀出**救災救護指揮中心指派案號**。
   同時讀出紀錄表上的 TEMSIS 與輸入值比對，**不符即中止**（防止查詢條件沒生效）。
4. 報表系統 → 案件列表；期間同樣近兩個月，填入派遣案號 → 查詢。
5. 點「救護紀錄」進入案件內部。
6. 決定目標：
   - 只有一個「調整為未結案」按鈕 → 該張即為目標。
   - 有多張 → **逐張開啟紀錄表比對 TEMSIS**，相符那張所在列的按鈕才是目標。
   - 比對不到、或相符那列沒有按鈕 → 回報「需人工處理」，**絕不挑一張**。
7. 印出每一筆的結果摘要（狀態＋原因）。

### 2.5 定位方式：以畫面文字，不靠 id
解鎖流程走的畫面沒有探測過，拿不到 id；且系統改版時 id 會變、畫面文字不太會變。
因此 `pageFinder.mjs` 改用近似人眼的方式定位：

| 要找的東西 | 作法 |
| --- | --- |
| 輸入欄 | 找到含標籤文字的儲存格 → 取**同列下一個儲存格**內的輸入欄（依序再試 `label[for]`、同列、父層容器） |
| 按鈕／連結 | 比對元素的文字、`alt`、`title`、`value`（舊系統的按鈕多是 `<img>`） |
| 「這是第幾筆案件」 | 依所在 `<tr>` 分組（同一列的多個按鈕屬同一筆，直接數按鈕會變兩倍） |
| 「這個解鎖按鈕屬於哪張紀錄表」 | **同一個 `<tr>`**（序號配對不安全，順序未必一致） |

比對前一律正規化（去空白與 `：*、,．` 等標點、轉大寫），因為舊系統的標籤常寫成
「T E M S I S 編號：」這種形式。

**`exact` 必須前後一致**：算出序號時與點擊時若一邊用完全相等、一邊用包含比對，
兩邊的符合集合不同，序號就會對到別張紀錄表。`救護紀錄` 用完全相等
（否則會連 `救護紀錄PDF` 一起命中），`救護紀錄PDF` 用包含（要同時吃到 `(桃)` 版）。

### 2.6 救護紀錄表的讀取
系統可能用三種方式呈現，`recordSheet.mjs` 三種都處理：

| 呈現方式 | 取得內容的作法 |
| --- | --- |
| 另開視窗顯示 PDF | 監聽回應，`content-type` 為 `application/pdf` 時取其位元組 |
| Chrome 內建閱讀器（DOM 讀不到） | 以同一登入狀態 `context.request.get()` 取回該網址 |
| 直接觸發下載 | 讀下載串流（**不落檔**） |
| 一般網頁 | 直接讀 `innerText` |

PDF 以 `pdfjs-dist` 轉文字，並指向套件內附的 `cmaps`／`standard_fonts`
（中文 PDF 多用 CID 字型，缺了會抽出亂碼），全程離線。

欄位擷取（`sheetFields.mjs`，純函式）：把文字壓掉空白後找標籤，再回到原文取標籤後方
第一段編號樣式的字串。**找不到就回傳 null，不猜值**。

### 2.7 個資保護（本流程特別注意）
| 規範 | 作法 |
| --- | --- |
| 紀錄表不落檔 | 不下載、不截圖、不寫暫存；全文只在記憶體，讀完立刻關閉視窗 |
| 只留兩個欄位 | 全文用完即棄，只保留指派案號與 TEMSIS 供比對 |
| 畫面與 log 一律遮蔽 | 編號只顯示末 4 碼（`maskCode`），例如 `*********0123` |
| 診斷資訊不含資料 | 找不到欄位／按鈕時只列出「欄位標籤與按鈕文字」，且 5 碼以上數字已遮蔽 |
| 快照沿用探測規則 | 只記結構，資料列（列數 > 5 的表格）內元素一律跳過 |

### 2.8 模組職責（第 2 章新增的部分）
