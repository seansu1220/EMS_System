## 0. 通則（所有小工具共用）

### 0.1 定位
- 位置：`tools/<工具名>/`，是**獨立於網頁系統的本機 CLI**。
- **不參與 `npm run build`、不部署上線**（`tsconfig` 只涵蓋 `src` 與 `vite.config.ts`）。
- 網頁的 `/tools` 頁只放使用說明，不呈現也不儲存任何查詢結果。

### 0.2 為什麼不做在網頁上
瀏覽器的同源政策禁止網站登入並讀取另一個網域的內容，因此網頁**在技術上無法**
代為登入外部系統、處理驗證碼或下載檔案。唯一繞法是架伺服器代抓，
但那會讓個案明細經過雲端主機，與個資要求牴觸，故不採用。

### 0.3 個資保護總則
凡工具會接觸到含個人資料的檔案，一律遵守：

| 規範 | 作法 |
| --- | --- |
| 不上雲 | 全程本機執行；不寫入 Firestore、不呼叫任何外部 API、不上傳檔案 |
| 原始明細用完即刪 | 只落在該工具的 `out/raw/`，統計後自動刪除（`--keep-raw` 才保留） |
| 產出只有統計數字 | 最終報表不含任何個人欄位 |
| 不進版控 | `.gitignore` 已排除 `tools/**/out/` |
| log 不印明細 | 只記錄流程、筆數與**欄位名稱**（欄名屬檔案結構，非個人資料） |
| 探測模式不取資料 | 只記錄欄位／按鈕／下拉選項名稱；資料列表（列數 > 5 的表格）內元素一律跳過；5 碼以上連續數字遮蔽；不截圖 |
| 驗證碼不自動破解 | 由使用者本人辨識輸入，不繞過來源系統的防自動化機制 |
| 帳密不硬寫 | 僅從該工具目錄的 `.env` 讀取（已 gitignore），且**禁用 `VITE_` 前綴**以免被打包進前端 |

### 0.4 執行方式
**一般使用一律雙擊 `捷徑/` 資料夾內的批次檔，不需輸入任何指令。**
批次檔會先確認 Node.js 是否存在（沒有就顯示官網下載連結），並在缺少套件時自動 `npm install`；
內容維持純 ASCII 訊息，避免主控台中文亂碼。

### 0.5 執行紀錄
每次執行的完整過程都會寫入該工具的 `out/last-run.log`（含失敗時的 frame 狀態），
排查問題不需請使用者抄寫終端機訊息。內容依設計不含個案明細。

## 1. 救護紀錄表查詢（到院前預警比率）

位置：`tools/ems-report/`

### 1.1 目的
自「桃園市政府消防局緊急救護管理系統」（`https://emsdt.tyfd.gov.tw/EmmWeb/`）
取得指定月份的救護紀錄，統計**各分隊的「到院前預警案件數 ÷ 總案件數」比率**。

### 1.2 執行方式
| 捷徑（`捷徑/` 資料夾內） | 用途 |
| --- | --- |
| `救護預警統計.bat` | 產生上個月的各分隊比較表（**日常使用就是這個**） |
| `設定登入帳密.bat` | 用記事本開啟 `.env` 填帳密，省去每次輸入（驗證碼仍須本人輸入） |
| `救護預警統計-設定用.bat` | 頁面結構探測，系統改版時才用 |

指令列等價寫法：

| 指令 | 用途 |
| --- | --- |
| `npm run tool:ems -- run` | 完整流程，預設查「上個月 1 號 ~ 最後一天」 |
| `npm run tool:ems -- run --month=2026-06` | 指定月份 |
| `npm run tool:ems -- run --keep-raw` | 保留原始匯出檔（含個資） |
| `npm run tool:ems -- probe` | 自動探測頁面結構（使用者只需登入） |
| `npm run tool:ems -- probe --manual` | 改為手動點選的探測模式 |
| `npm run tool:ems:test` | 全部單元／整合測試 |

以本機已安裝的 Chrome 執行（`playwright-core` + `channel: 'chrome'`），不另外下載瀏覽器。
**Node.js 並非 Windows 內建**，該台電腦需自行安裝。

### 1.3 自動化流程
1. 開啟登入頁；帳密可自 `.env` 代填，**驗證碼由使用者在瀏覽器輸入**。
   程式輪詢等待登入完成，再等 `contentSidemenu`／`contentFrame` 兩個 frame 真正出現才續行。
2. 左側選單 → 報表系統 → 救護紀錄表查詢。
3. 填入共同查詢條件，**填完一律回讀驗證**：
   - 查詢期間（起日 `00:00:00`、迄日 `23:59:59`）
   - 救護狀態＝「已結案」
   - **送醫情形＝「送醫」**（未運送案件如誤報、拒送、現場死亡不會有到院前預警，
     算進母數會稀釋比率）
4. 院前預警不設限 → 查詢 → 匯出 Excel（**總案件數**）。
5. 院前預警＝「到院前傳送預警」→ 查詢 → 匯出 Excel（**預警案件數**）。
6. 本機解析兩份 Excel，依分隊彙總，輸出比較表後刪除原始明細。

彈出式視窗封鎖不需另外處理：自動化瀏覽器預設允許彈出視窗與檔案下載。

### 1.4 目標系統的實際結構（探測結果）
登入後為 frameset 版面，全站以 POST 導頁，frame 物件每次導航都會重建，**取用前須重新查找**。

| 項目 | 值 |
| --- | --- |
| 內容框 / 左選單 / 上方列 | `contentFrame` / `contentSidemenu` / `header` |
| 救護紀錄表查詢 AP 代號 | `wap119.RPS64101030` |
| 查詢期間 | `#_txtFromDate`、`#_txtToDate`（My97DatePicker，**唯讀，格式 `yyyy-MM-dd HH:mm:ss`**） |
| 救護狀態 | `#_selSTATUS`，已結案＝`0` |
| 送醫情形 | `#_selSPA11`，未運送＝`0`、**送醫＝`1`** |
| 院前預警 | `#_selPreHOSPWarning`，到院前傳送預警＝`1` |

### 1.6 統計規則
- **分隊欄位以「內容」判定而非欄名**：值以「分隊／大隊／中隊」結尾的比例達 80% 以上者即為分隊欄。
  內容判斷不出來時才退回欄名比對（`SQUAD_COLUMN_CANDIDATES`），且「包含」比對取最短欄名。
- 比率＝該分隊預警案件數 ÷ 該分隊總案件數；總案件數為 0 時比率為 `null`（不做除以零）。
- 排序：總案件數由多到少，同數量再依分隊名稱，確保每次輸出順序一致。
- 報表含合計列；Excel 的比率欄以數值寫入並套 `0.0%` 格式，方便再排序或製圖。
- **合理性檢查**：資料超過 100 筆卻只分出少於 3 個分隊時直接中止並列出實際欄名，
  避免產出明顯錯誤的報表。
- 解析失敗時**保留原始檔**並輸出「只有欄名與筆數」的診斷資訊，不輸出任何資料格內容。

### 1.7 實跑踩過的坑（維護時務必先看這段）

| 現象 | 真正原因 | 對策 |
| --- | --- | --- |
| 找不到 `contentSidemenu` | 「驗證碼欄位消失」只代表表單送出，frameset 尚未建好 | 等必要 frame 真正出現（`waitForAppReady`） |
| 導航逾時 | **上方 `header` 那排報表連結要進入報表系統後才存在**，登入直後只有「首頁」 | 一律走左側選單，備援為直接載入內容框網址 |
| 探測掃不到查詢／匯出鈕 | 兩者是 `<img>` 圖片按鈕，不是 input/button | 探測改為掃描所有帶 onclick 的元素與圖片 |
| 進階搜尋展開後又收起來 | 展開函式是 toggle，盲目呼叫兩次會收合 | 先檢查目標欄位可見性再決定是否切換 |
| 撈到全部資料（10185 筆） | 日期格式為 `yyyy-MM-dd HH:mm:ss`，只處理年月日會讓 `HH:mm:ss` 原樣留在字串裡 | 支援時分秒；起日 `00:00:00`、**迄日 `23:59:59`** |
| 報表只有一個叫「V」的分隊 | 匯出檔沒有名為「分隊」的欄，欄名模糊比對抓到「分隊 自行受理」勾選欄 | 改以欄位內容判定分隊欄 |
| `cannot save file` | SheetJS 的 ESM 版必須先 `set_fs(fs)` | 統一由 `xlsxNode.mjs` 取用 |
| 常數 `is not defined` | `node --check` 只驗語法、不驗未定義引用 | 測試需**實際執行到函式內部**（見 `session.test.mjs`） |
| 打驗證碼時焦點一直被搶 | 等待迴圈每秒重填帳密並把游標移到驗證碼欄 | **只在欄位空白時才代填**，填完只移動一次焦點 |

### 1.9 後續規劃（待使用者提供細節）

- **嵌入另一份資料做數據增減**：使用者表示之後會再提供一份資料，
  用來對目前的統計結果做增減調整。細節（資料來源、格式、增減規則、
  是要調整分子／分母或另立欄位）待使用者說明後再行規劃。
  屆時預期的改動範圍：
  - 資料讀取：沿用 `workbook.mjs` 或新增對應的讀取模組
  - 調整規則：以純函式實作於 `aggregate.mjs`，維持可單獨測試
  - 報表輸出：`report.mjs` 視需要增列「調整前／調整後」欄位
  - 個資規範不變：新資料若含個人資料，一律比照 0.3 節處理
