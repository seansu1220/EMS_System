## 0. 通則（所有小工具共用）

### 0.1 定位
- 位置：`tools/<工具名>/`，是**獨立於網頁系統的本機 CLI**。
- **不參與 `npm run build`、不部署上線**（`tsconfig` 只涵蓋 `src` 與 `vite.config.ts`）。
- 網頁的 `/tools` 頁只放使用說明，不呈現也不儲存任何查詢結果。

### 0.2 為什麼不做在網頁上
瀏覽器的同源政策禁止網站登入並讀取另一個網域的內容，因此網頁**在技術上無法**
代為登入外部系統、處理驗證碼或下載檔案。唯一繞法是架伺服器代抓，
但那會讓個案明細經過雲端主機，與個資要求牴觸，故不採用。

### 0.3 個資保護總則
凡工具會接觸到含個人資料的檔案，一律遵守：

| 規範 | 作法 |
| --- | --- |
| 不上雲 | 全程本機執行；不寫入 Firestore、不呼叫任何外部 API、不上傳檔案 |
| 原始明細用完即刪 | 只落在該工具的 `out/raw/`，統計後自動刪除（`--keep-raw` 才保留） |
| 產出只有統計數字 | 最終報表不含任何個人欄位 |
| 不進版控 | `.gitignore` 已排除 `tools/**/out/` |
| log 不印明細 | 只記錄流程、筆數與**欄位名稱**（欄名屬檔案結構，非個人資料） |
| 探測模式不取資料 | 只記錄欄位／按鈕／下拉選項名稱；資料列表（列數 > 5 的表格）內元素一律跳過；5 碼以上連續數字遮蔽；不截圖 |
| 驗證碼不自動破解 | 由使用者本人辨識輸入，不繞過來源系統的防自動化機制 |
| 帳密不硬寫 | 僅從該工具目錄的 `.env` 讀取（已 gitignore），且**禁用 `VITE_` 前綴**以免被打包進前端 |

### 0.4 執行方式
**一般使用一律雙擊 `捷徑/` 資料夾內的批次檔，不需輸入任何指令。**
批次檔會先確認 Node.js 是否存在（沒有就顯示官網下載連結），並在缺少套件時自動 `npm install`；
內容維持純 ASCII 訊息，避免主控台中文亂碼。

### 0.5 執行紀錄
每次執行的完整過程都會寫入該工具的 `out/last-run.log`（含失敗時的 frame 狀態），
排查問題不需請使用者抄寫終端機訊息。內容依設計不含個案明細。

## 1. 救護紀錄表查詢（到院前預警比率）

位置：`tools/ems-report/`

### 1.1 目的
自「桃園市政府消防局緊急救護管理系統」（`https://emsdt.tyfd.gov.tw/EmmWeb/`）
取得指定月份的救護紀錄，統計**各分隊的「到院前預警案件數 ÷ 總案件數」比率**。

### 1.2 執行方式
| 捷徑（`捷徑/` 資料夾內） | 用途 |
| --- | --- |
| `救護預警統計.bat` | 產生上個月的各分隊比較表（**日常使用就是這個**） |
| `設定登入帳密.bat` | 用記事本開啟 `.env` 填帳密，省去每次輸入（驗證碼仍須本人輸入） |
| `救護預警統計-設定用.bat` | 頁面結構探測，系統改版時才用 |
| `檢查增減試算表.bat` | 確認增減用的 Google 試算表讀不讀得到，並列出欄位結構 |

指令列等價寫法：

| 指令 | 用途 |
| --- | --- |
| `npm run tool:ems -- run` | 完整流程，預設查「上個月 1 號 ~ 最後一天」 |
| `npm run tool:ems -- run --month=2026-06` | 指定月份 |
| `npm run tool:ems -- run --keep-raw` | 保留原始匯出檔（含個資） |
| `npm run tool:ems -- probe` | 自動探測頁面結構（使用者只需登入） |
| `npm run tool:ems -- probe --manual` | 改為手動點選的探測模式 |
| `npm run tool:ems -- check-sheet` | 檢查增減用的 Google 試算表 |
| `npm run tool:ems:test` | 全部單元／整合測試 |

以本機已安裝的 Chrome 執行（`playwright-core` + `channel: 'chrome'`），不另外下載瀏覽器。
**Node.js 並非 Windows 內建**，該台電腦需自行安裝。

### 1.3 自動化流程
1. 開啟登入頁；帳密可自 `.env` 代填，**驗證碼由使用者在瀏覽器輸入**。
   程式輪詢等待登入完成，再等 `contentSidemenu`／`contentFrame` 兩個 frame 真正出現才續行。
2. 左側選單 → 報表系統 → 救護紀錄表查詢。
3. 填入共同查詢條件，**填完一律回讀驗證**：
   - 查詢期間（起日 `00:00:00`、迄日 `23:59:59`）
   - 救護狀態＝「已結案」
   - **送醫情形＝「送醫」**（未運送案件如誤報、拒送、現場死亡不會有到院前預警，
     算進母數會稀釋比率）
4. 院前預警不設限 → 查詢 → 匯出 Excel（**總案件數**）。
5. 院前預警＝「到院前傳送預警」→ 查詢 → 匯出 Excel（**預警案件數**）。
6. 本機解析兩份 Excel，依分隊彙總。
7. 讀取增減試算表，扣除期間內應排除的案件（見 1.7）。
8. 輸出兩個分頁的報表後刪除原始明細。

彈出式視窗封鎖不需另外處理：自動化瀏覽器預設允許彈出視窗與檔案下載。

### 1.6 報表格式
比照使用者既有的人工報表（`6月份到院前預警比例.xlsx`），輸出**兩個分頁**：

| 分頁 | 內容 |
| --- | --- |
| `到院前預警比例` | 各大隊合計列 ＋ 其轄下分隊（依 `BRIGADES` 設定的官方順序） |
| `排序` | 各分隊依**到院前預警率由高到低** |

兩個分頁格式相同：
- 第 1 列為標題並跨 4 欄合併，內容為 `本局{起}-{迄}到院前預警案件執行率`（例：`本局6/1-6/30…`）
- 第 2 列欄位標題：（留白）｜`有送醫有預警案件`｜`有送醫案件`｜`到院前預警率`
- 比率欄以數值寫入並套 `0.00%` 格式，可直接在 Excel 內再排序或製圖

大隊與轄下分隊的對應表定義於 `config.mjs` 的 `BRIGADES`（4 大隊、41 分隊），
順序取自既有報表。匯出檔中出現但不在對應表內的單位會歸入「未對應大隊」並在紀錄檔提出警告，
**不會被默默丟掉**。

### 1.7 統計規則
- **分隊欄位以「內容」判定而非欄名**：值以「分隊／大隊／中隊」結尾的比例達 80% 以上者即為分隊欄。
  內容判斷不出來時才退回欄名比對（`SQUAD_COLUMN_CANDIDATES`），且「包含」比對取最短欄名。
- 分隊比率＝該分隊預警案件數 ÷ 該分隊送醫案件數；送醫案件為 0 時比率為 `null`（不做除以零）。
- **大隊比率＝該大隊預警案件總數 ÷ 送醫案件總數（加權）**，使用者於 2026-07-28 確認採此算法。
  ⚠ 使用者先前的人工報表取的是「各分隊比率的平均」，兩者相差約 0.2~1.0 個百分點
  （案件量小的分隊在平均法中權重被放大），故新舊報表的大隊數字不會完全相同，屬預期差異。
- `排序`分頁依預警率由高到低；比率相同時案件多的在前，再相同則依名稱，確保輸出順序穩定。
- **合理性檢查**：資料超過 100 筆卻只分出少於 3 個分隊時直接中止並列出實際欄名，
  避免產出明顯錯誤的報表。
- 解析失敗時**保留原始檔**並輸出「只有欄名與筆數」的診斷資訊，不輸出任何資料格內容。

#### 增減試算表的扣除規則（v1.11.6 起）
使用者維護一份 Google 試算表，列出應自統計中排除的案件。規則（2026-07-28 確認）：

- 讀**第一個分頁**（`EMS_ADJUST_SHEET_GID` 留白即為第一個分頁）。
- 每一列代表一件應排除的案件；**日期落在查詢期間內**者才計入。
- **只扣該分隊的送醫案件數（分母），預警案件數（分子）不動**
  ——把這些案件排除在評比之外。使用者於 2026-07-29 再次確認採此算法。
  ⚠ **與 6 月以前的人工報表口徑不同**：舊報表是把同一批案件**加到分子**
  （視為實際有預警、只是系統未記錄），全局比率因此高約 0.02 個百分點，
  跨期間比較趨勢時須留意。詳見 1.11。
- 日期欄與分隊欄**以內容判定**（日期可解析比例 ≥ 70%、以分隊/大隊/中隊結尾比例 ≥ 70%），
  不依賴欄名，使用者改欄名不影響。
- 日期容錯：`2026-06-01`、`2026/6/1`、`2026年6月1日`、後接時間、以及**民國年**（`115/6/1`）。
- 試算表寫「桃園」而非「桃園分隊」也能對應（比對時自動補「分隊」）。
- **找不到對應分隊、或扣到分母小於分子時會提出警告**，不會默默套用。
- **日期空白的列屬正常情形**（使用者 2026-07-28 確認），一律不列入扣除，
  只以一般訊息附記筆數，不視為警告。
- 未設定 `EMS_ADJUST_SHEET_URL` 時略過扣除，不影響主流程。

存取方式：以 Google 試算表的 CSV 匯出網址讀取，**免 API 金鑰**，
但該試算表須設為「知道連結的任何人 → 檢視者」。

### 1.8 實跑踩過的坑（維護時務必先看這段）

| 現象 | 真正原因 | 對策 |
| --- | --- | --- |
| 找不到 `contentSidemenu` | 「驗證碼欄位消失」只代表表單送出，frameset 尚未建好 | 等必要 frame 真正出現（`waitForAppReady`） |
| 導航逾時 | **上方 `header` 那排報表連結要進入報表系統後才存在**，登入直後只有「首頁」 | 一律走左側選單，備援為直接載入內容框網址 |
| 探測掃不到查詢／匯出鈕 | 兩者是 `<img>` 圖片按鈕，不是 input/button | 探測改為掃描所有帶 onclick 的元素與圖片 |
| 進階搜尋展開後又收起來 | 展開函式是 toggle，盲目呼叫兩次會收合 | 先檢查目標欄位可見性再決定是否切換 |
| 撈到全部資料（10185 筆） | 日期格式為 `yyyy-MM-dd HH:mm:ss`，只處理年月日會讓 `HH:mm:ss` 原樣留在字串裡 | 支援時分秒；起日 `00:00:00`、**迄日 `23:59:59`** |
| 報表只有一個叫「V」的分隊 | 匯出檔沒有名為「分隊」的欄，欄名模糊比對抓到「分隊 自行受理」勾選欄 | 改以欄位內容判定分隊欄 |
| `cannot save file` | SheetJS 的 ESM 版必須先 `set_fs(fs)` | 統一由 `xlsxNode.mjs` 取用 |
| 常數 `is not defined` | `node --check` 只驗語法、不驗未定義引用 | 測試需**實際執行到函式內部**（見 `session.test.mjs`） |
| 打驗證碼時焦點一直被搶 | 等待迴圈每秒重填帳密並把游標移到驗證碼欄 | **只在欄位空白時才代填**，填完只移動一次焦點 |
| 匯出後乾等 3 分鐘才報錯 | 系統匯出在伺服器端拋例外（頁面顯示 `Error!!! ..._btnExcel()`）時**不會有任何下載**，只等下載事件必然等到逾時 | 監看頁面是否出現 `Error!!!` 字樣，出現即立刻中止；並自動重新查詢後重試一次 |
| 讀 Google 試算表得到 HTTP 400 | 預設帶了 `gid=0`，但**第一個分頁的 gid 未必是 0**（原始分頁被刪過就會變） | 未指定 gid 時**不帶該參數**，Google 即回傳第一個分頁；帶了 gid 而收到 400 時自動退回不帶 |

### 1.11 與人工報表的差異分析（2026-07-29）

逐分隊比對本工具產出與使用者 6 月人工報表，41 個分隊全數對上，16 個分隊有差異：

| 項目 | 本工具 | 人工報表 | 差異 |
| --- | --- | --- | --- |
| 到院前預警案件（分子） | 7,290 | 7,324 | −34 |
| 送醫案件（分母） | 7,664 | 7,701 | −37 |
| **全局預警率** | **95.12%** | **95.10%** | **+0.02pp** |

**原因：兩者把增減試算表的 35 件加在不同位置**（由使用者提出、經資料驗證確認）：

| 做法 | 分子 | 分母 | 結果 |
| --- | --- | --- | --- |
| 人工報表 | 原始值 **＋35** | 原始值 | 7,325 / 7,699 ＝ 95.14% |
| 本工具 | 原始值 | 原始值 **−35** | 7,290 / 7,664 ＝ 95.12% |

**決定性驗證**：「送醫−預警」（有送醫但沒預警的件數）在兩種做法下都不會改變，
實測 **41 個分隊中有 38 個完全相同**，證明兩份報表調整的量一致、只是位置不同。
再以預測值比對：「加分子」假設預測分子為 7,325，實際 7,324，**誤差僅 1 件**；
而「人工報表未做任何調整」假設的誤差達 34 件，可排除。

殘餘差異（分子 −1、分母 +2，集中於龍岡、復旦、巴陵各 1 件）屬系統資料自 6 月後的正常異動。

> ⚠ 曾一度誤判為「這些案件事後已在系統中更正、不再登記預警」，
> 經上述驗證推翻。保留此註記以免日後重複同樣的錯誤推論。

**採用的算法（使用者 2026-07-29 確認）：維持扣分母**，
即把這些案件排除在評比之外，而非視為已預警。
因此**本工具的數字會略低於 6 月以前的人工報表**（約 0.02 個百分點），
跨期間比較趨勢時需留意口徑已改變。

### 1.10 增減試算表的設定

| `.env` 參數 | 用途 |
| --- | --- |
| `EMS_ADJUST_SHEET_URL` | 試算表網址（貼整串即可，程式自行解析 ID 與 gid） |
| `EMS_ADJUST_SHEET_GID` | 選填，指定分頁 gid；**留白即讀第一個分頁**（建議留白） |

網址放 `.env`（已 gitignore）而非寫死在程式，因此不會外流到 GitHub。
執行 `檢查增減試算表.bat` 可在不開瀏覽器、不登入救護系統的情況下確認：
能否讀取、共幾列幾欄、各欄型態、日期欄與分隊欄判定結果，
以及**指定期間內每個分隊會被扣幾件**（試算，不會寫出報表）。

個資保護：任何輸出都**不顯示試算表網址**，診斷資訊**不含任何儲存格內容**，
僅顯示欄名、筆數與扣除件數，並以測試斷言釘住。
