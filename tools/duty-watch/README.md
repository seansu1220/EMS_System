# 值班監看（兩個系統一起顧）

一個視窗、開著一整天，同時看顧兩件事：

| 系統 | 做什麼 | 怎麼觸發 |
| --- | --- | --- |
| 救護系統 | 線上解鎖工單 | 各分隊在網頁上送出申請，它自動處理並回寫 |
| 一站通 | 大量傷患系統權限開通 | 你把名單貼進這個視窗 |

**重點是不必重複登入**：早上各登入一次，之後靠心跳維持，一整天都不用再打驗證碼。

---

## 怎麼用

雙擊 `捷徑\值班監看.bat`：

1. **會開兩個瀏覽器視窗**，依序登入（帳號密碼會自動填好，你只要打驗證碼）
   - 第 1 個：救護系統
   - 第 2 個：一站通
2. 之後這個黑視窗就放著別關
3. 要開通權限時，**直接把名單貼進黑視窗**（一行一位：`單位,姓名`），
   貼完在**空白行按一次 Enter** 就開始做
   （貼不上去時：在視窗內按**滑鼠右鍵**就是貼上）
4. 解鎖申請不用你管，有人送出就會自動處理

### 掉線了怎麼辦

畫面會**響一聲**並告訴你是哪一邊掉線，到**那個**瀏覽器視窗重新打驗證碼即可。
這段期間：

- 另一個系統**照常運作**（兩邊完全獨立）
- 掉線那邊的工作會排隊等著，登入後接著做
- 監看**不會自己結束**，就算整晚沒人理它

---

## 指令（不想用捷徑時）

```
npm run tool:duty                    試跑：兩邊都顧，但不解鎖、開通也不按確定
npm run tool:duty -- --execute       真的處理
npm run tool:duty -- --only=unlock   只顧救護系統的解鎖工單
npm run tool:duty -- --only=mci      只顧一站通的權限開通
npm run tool:duty -- --fresh-login   兩邊都重新登入
```

`捷徑\不常用\值班監看-試跑.bat` 是試跑版，可以拿來**量登入到底能撐多久**：
放著跑，掉線時畫面上會寫是第幾點幾分、撐了多久。

---

## 幾件刻意這樣設計的事

- **兩個瀏覽器視窗，不合併成一個。** 救護系統的登入流程是天天在用、已經實測過的，
  為了新功能去動它不划算；分開之後一邊掉線也不會干擾另一邊。
- **兩邊完全獨立。** 一邊掉線、出錯、或還在等你重登，另一邊照常做事。
  這條有測試守著（`dutyLoop.test.mjs`）。
- **驗證碼仍然由你本人打。** 這個工具省下的是**重複登入**，不是驗證碼本身——
  不做自動辨識、不接第三方服務（見 `docs/TOOLS_SPEC.md` 0.3）。
- **預設試跑。** 捷徑裡的正式版有加 `--execute`；直接下指令的話預設不會動手。
- **邊跑邊寫紀錄**（`out/duty-watch.log`）。監看多半是被直接關掉視窗而結束，
  只在結束時落檔等於沒有紀錄——救護系統那邊實際損失過一次。

---

## 心跳是怎麼做的

各自做一次**流程本來就會做的無害動作**，讓伺服器知道還有人在用：

- 救護系統：切到「救護紀錄表查詢」頁（不送出任何查詢）
- 一站通：回主畫面再進一次「帳號子系統權限」（不送出任何查詢）

預設每 5 分鐘一次。救護系統實測這個節奏可以撐 6 小時 46 分；
**一站通能撐多久還沒量過**，用試跑版放著跑一天就知道了。
